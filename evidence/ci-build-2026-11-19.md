## The budget

Terraform still refuses this resource:

```
billingbudgets.googleapis.com API requires a quota project, which is not set by default
```

That is a property of the transport, not of the configuration: the provider's billing client uses
Application Default Credentials, and Terraform was driven by a short-lived OAuth token for
`<operator account>`. Enabling the API did not help.

The budget itself **does exist**, created with `gcloud` (which supplies its own quota project):

```
display name : gcp-proof-platform-dev-monthly
id           : billingAccounts/AAAAAA-BBBBBB-CCCCCC/budgets/<budget-id>
amount       : GBP 15, calendar month
filter       : projects/<project-number>, label workload=gcp-proof-platform
thresholds   : 80% and 100%, email notification channel
```

To bring it under Terraform, the credential has to be ADC for the right account, with a quota
project:

```bash
gcloud auth application-default login --account=<operator account>
gcloud auth application-default set-quota-project gcp-proof-platform
terraform import google_billing_budget.budget \
  billingAccounts/AAAAAA-BBBBBB-CCCCCC/budgets/<budget-id>
```

**Closed later the same day.** Setting the quota project on ADC was not enough: the Go API client
behind the provider does not inherit it, so the import kept failing. The fix is in the provider
block:

```hcl
user_project_override = true
billing_project       = var.project_id
```

With that, the import succeeded and `terraform plan -target=google_billing_budget.budget` reports
**"No changes. Your infrastructure matches the configuration."** The budget is now managed by
Terraform, and a full plan no longer offers to create a duplicate.

## WIF after the teardown

Destroying the platform soft-deletes Workload Identity pools and providers for 30 days, so
recreating them returns `409 Requested entity already exists`. Both were undeleted and imported:

```bash
gcloud iam workload-identity-pools undelete github-pool --location=global
gcloud iam workload-identity-pools providers undelete github-oidc \
  --workload-identity-pool=github-pool --location=global
terraform import google_iam_workload_identity_pool.github …
terraform import google_iam_workload_identity_pool_provider.github …
```

The `ci_wif` binding is applied again. The pool is `ACTIVE` and the provider exists.

## What is still true

- The full platform (VM, VPC, monitoring) is **deliberately absent**; a plain `terraform plan` wants
  to recreate it, because the configuration describes it. That is expected after a targeted teardown,
  not drift.
- Builds are submitted by hand. There is no Cloud Build trigger wired to the repository, so "push
  builds" is still a manual step.
- The successful build's step statuses are in Cloud Build, not in this repository beyond this table.
